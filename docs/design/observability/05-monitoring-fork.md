# Monitoring fork: status, checks, incidents and history

Research checked **2026-11-07**, Bedrock base `e8336f9`. This is a selection report; no implementation has been started. Read [report 04](04-uptime-alerting.md) first, then [owner decision #2](DESIGN.md#owner-decisions-2026-11-07), reports 01–03, [architecture §§1–2,6](../../../ARCHITECTURE.md) and reference §§4–5,8,10–11. Measurements below are observations; work estimates and budgets are proposals. Upstream source links are pinned wherever practical.

## 1. Recommendation

- **Fork Gatus, selectively adapt its status UI and monitoring model into one Bun/TypeScript pebble.** Its grouped cards, health strips, condition details, response graphs and announcements offer the strongest visual starting point for this small scope. Retain real upstream markup/styles and attribution while porting the selected Vue components to the existing React/TypeScript client stack; rewrite the Go backend with `definePebble`, Drizzle and one SQLite file. This is a substantial derivative fork, not a claim that Gatus already runs as a pebble. [Inspected UI screenshot][g-screen], [card source][g-card], [details source][g-detail], [SQLite model][g-sql], [Bedrock contract](../../../ARCHITECTURE.md#6-the-pebble-contract).
- **Use a small Upptime-style Actions prober, not a second monitoring-project fork.** Put a TypeScript HTTP prober and a static export of the same Gatus-derived public view in the public fork. GitHub-hosted standard Linux runners observe the canary, persist redacted results independently, open/close an issue for outage email, and publish GitHub Pages. The home pebble later imports those observations; its availability must never gate the probe, notification or public page. Upptime proves this separation, but its Git/Issues-dependent backend and 199 MiB installed prober tree are unnecessary inside Bedrock. [Upptime workflow][u-workflow], [updater][u-update], [Actions billing][gh-billing]; measurements in §3.
- **Also enable Cloudflare Tunnel Health Alert to owner email.** It covers connector loss independently of Actions and the laptop. It is included with all Zero Trust plans, but a healthy tunnel can still front a broken application; it complements HTTP probing. Do not confuse it with the standalone Health Checks product. [Cloudflare tunnel health and notifications][cf-tunnel].
- **Make the fork and a minimal external status page public; keep private operational detail in the pebble.** Publish only “Home cloud”, its intentionally public canary hostname, observation times, measured availability/coverage and redacted outage history. No individual pebble names by default. This gives the owner an accessible status page during a home outage and qualifies the public workflow for free standard runners. The licence does not require Gatus's source or operational data to be public; the hosting choice does. [Apache licence][g-license], [Actions terms][gh-billing], [Pages availability][gh-pages]; exposure details in §6.

| Candidate | Best fit / win | Main cost under Bedrock's contract | Decision; estimated focused developer-days |
|---|---|---|---|
| **Gatus** | Polished compact status UI; explicit results, events, thresholds, SQL rollups | Go backend fully rewritten; real incident lifecycle added; selected Vue UI ported | **Choose; 10–16** |
| Upptime | Best existing off-box + independently hosted public status path | Git/Issues data ownership replaced locally; Sapper/Svelte 3 frontend; native curl/prober dependencies | Strong external reference; **12–20** as the pebble |
| Uptime Kuma | Rich interactive dashboard, monitor editor, heartbeat/incident history | Broad Node/CommonJS, Express, Socket.IO, RedBean/Knex system must be dismantled | Too much inherited surface; **15–25** |
| Healthchecks | Excellent missing-job deadlines, start/success/fail and grace model | Python/Django backend rewritten; active HTTP checks and richer public status/incident UI added | Job-monitoring reference; **15–25** |
| Statping-ng | Services, success/failure history and incident updates already separate | Go/GORM rewrite, Vue 2 frontend, stale default branch, GPL distribution obligations | Reject; **18–30** |

These are engineering estimates, not upstream promises or measured implementation times. Each includes a narrow pebble, the same external watcher/export, tests, privacy controls, attribution and documentation; excludes the daemon telemetry/readiness/outbox milestones already in [DESIGN](DESIGN.md#build-order). Assume one developer familiar with Bedrock, HTTP checks only, a few components, and no upstream feature parity. Gatus's advantage is the combination of reusable visual code and a small model, **not** native Go memory savings after a TypeScript rewrite. Candidate evidence follows in §§2–4. No sixth candidate was added: the inspected shortlist already provides a viable choice, with no primary evidence establishing a clearly better alternative.

Disk figures are rounded-up MiB from `du -sm node_modules`, exclude package-manager caches, repository files, frontend release assets and browsers. They are **installed disk allocation, not RSS, download size or production browser payload**. Dependencies are direct manifest declarations; installer package counts are reported separately, not an audited transitive graph.

- **Kuma runtime smoke measurement succeeded.** Downloaded the [2.5.9 `dist.tar.gz` release](https://github.com/louislam/uptime-kuma/releases/tag/2.5.9) (**7,557,888 bytes**, **13,172 KiB** extracted allocation), then installed only the [SQLite N-API prebuild](https://github.com/louislam/node-sqlite3/releases/tag/v15.1.6) using `node-pre-gyp install --fallback-to-build=false`. This short post-migration observation is **not steady-state monitoring memory**, and does not predict Bun-port memory. [Startup][k-server], [DB selection][k-db].

## 4. What each fork would retain and replace

### Gatus — selected

- **Wins / appearance:** inspected the upstream dark-dashboard JPEG: responsive-looking grouped cards, bright health strips, restrained dark chrome, visible failures and endpoint search. Current source adds endpoint detail graphs, condition tooltips and active/past announcements. This is the best visual source for the owner's “spectacular” requirement in my judgment; no browser interaction, mobile or accessibility certification was performed. [Viewed screenshot][g-screen], [home][g-home], [details][g-detail], [announcements][g-ann].
- **Checks / history:** endpoints contain conditions; a result has success, time, duration, HTTP status, errors and individual condition outcomes. SQL separates endpoints, results, condition results, state events, uptime counters and triggered alerts. Events are `START`, `HEALTHY`, `UNHEALTHY`; hour buckets roll up to days. Alerts have separate failure and recovery thresholds. **Announcements are dated communication, not a durable incident entity with acknowledgment, affected components and an update thread.** Default storage is memory, so persistence must be chosen explicitly in upstream. [Result][g-result], [event][g-event], [SQLite DDL][g-sql], [rollups](https://github.com/TwiN/gatus/blob/4b84fa2d591a364325b17d81ade755523508dc0b/storage/store/sql/sql.go#L1057), [thresholds][g-alert], [announcement model][g-ann], [storage defaults][g-readme].
- **Keep / rewrite:** preserve and adapt the card/strip/detail/announcement markup, styling, grouping and condition-result semantics. Port selected Vue scripts to existing React/TSX; retain derivation notices per file. Rebuild HTTP scheduling, persistence, ingestion and incident CRUD in Bun/Drizzle; discard Go/Fiber, the condition-expression DSL, multi-protocol suites, remote-instance federation, OIDC and dozens of notification integrations. Raw Go is a reference, not imported runtime code. No new server dependency is needed; reuse existing React rather than adding Vue/Chart.js. An initial small latency graph can use SVG. This is a proposal, not an already implemented dependency-free port. [Frontend dependencies][g-pkg], [Go dependencies][g-go], [existing Bedrock UI stack](../../../packages/ui/package.json).
- **Licence:** Apache-2.0. Preserve its licence, relevant copyright/attribution notices, label modified files, and carry forward any applicable NOTICE content; none was found in tracked files at the inspected revision. Apache includes a patent grant and excludes trademark permission. Keep an upstream attribution in the UI and README as the owner requires; a footer is not a substitute for the licence. No source-publication obligation for this permissive fork. [Actual licence §§3–4,6][g-license].
- **Off-box / effort:** upstream accepts externally pushed results with a bearer token and heartbeat expiry, but pushing only to a dead home instance loses evidence. Pair with the independent Actions journal and Pages export in §5. **10–16 days:** 3–5 visual port, 3–4 checks/storage/incidents, 2–3 external watcher/reconciliation, 2–4 validation/privacy/docs; integration uncertainty is included. [External-result handler][g-external], [external-endpoint docs][g-readme].

### Upptime — best off-box system, weaker local fork foundation

- **Wins / appearance:** inspected official screenshots of the status cards and incident/history views: clear typography, large response-area graphs, duration selectors and incident narratives. Static frontend can survive laptop failure. TypeScript checking code is available. [Viewed card screenshot][u-screen], [incident screenshot](https://github.com/upptime/upptime.js.org/blob/7eaf12814753f3faa9accbc5544aa8062bf338b9/static/img/screenshot-incident.png), [live demo](https://demo.upptime.js.org/), [updater][u-update].
- **Model / losses:** YAML configuration declares sites; `history/<slug>.yml` holds current status/code/latency/last update, Git commits hold history, `summary.json` holds aggregates, labelled GitHub Issues/comments represent incidents/recovery and maintenance. The site fetches raw GitHub data and Issues; the uptime helper uses issue-open/close time rather than observed-coverage accounting. **Current v1.46.5 does retry failures inside one run (2 s then 10 s); it still does not implement report 04's three failed scheduled observations and two successful observations.** This corrects report 04's older “instant incident” simplification. [Actual history file](https://github.com/upptime/upptime/blob/e04e239ea4cf6a65988893be052d344601acafb2/history/google.yml), [update/retries][u-update], [uptime helper][u-uptime], [site data loading][u-live], [incident history][u-history]. Summary cleanup can also delete brief resolved incidents unless disabled; an auditable fork must retain their evidence. [Cleanup source](https://github.com/upptime/uptime-monitor/blob/74f0683383384927e064d76a5f21f340d6af36fc/src/summary.ts#L60).
- **Keep / rewrite:** could retain status components/themes, check configuration ideas and selected TypeScript response classification; replace Git-backed writes, Issues APIs and all browser GitHub dependencies with Drizzle and Bedrock routes. Replace Sapper/Svelte 3 tooling, native `node-libcurl`, notification SDK and shell Git orchestration. That loses much of Upptime's distinctive implementation locally; “TypeScript” does not make its data ownership compatible. Three upstream repositories also need explicit provenance, not just a template fork with an opaque latest package. [Manifests][u-monitor-pkg], [status toolchain][u-status-pkg], [Git operations](https://github.com/upptime/uptime-monitor/blob/74f0683383384927e064d76a5f21f340d6af36fc/src/helpers/git.ts).
- **Licence / off-box / effort:** MIT, copyright Anand Chowdhary; preserve copyright + permission text for template, action and UI portions, including distributed substantial browser code. Public source is not required by MIT, but stock public status expects public GitHub data and free standard Actions favours a public repository. Keep the off-box architecture, without embedding the action's full dependency tree or forking a second project. **12–20 days** for local storage/UI/data-source replacement plus the common external kit. [Template licence](https://github.com/upptime/upptime/blob/e04e239ea4cf6a65988893be052d344601acafb2/LICENSE), [monitor licence](https://github.com/upptime/uptime-monitor/blob/74f0683383384927e064d76a5f21f340d6af36fc/LICENSE), [site licence](https://github.com/upptime/status-page/blob/7a5549f935bf73be827fe42b9bfe3bd61101ebbb/LICENSE), [private-repository caveat](https://upptime.js.org/docs/faq/#my-status-website-doesnt-work-with-my-private-repository).

### Uptime Kuma — attractive, but a large application to dismantle

- **Wins / appearance:** viewed the README screenshot: dark sidebar, instant green/red heartbeat strips, latency chart and uptime cards; the screenshot is an older upstream example, not evidence of every 2.5.9 screen. Current stable sources include a monitor editor, multiple status pages, groups, heartbeat history and manual incident history. [Viewed screenshot][k-screen], [status page][k-page], [incident handlers][k-incidents].
- **Model / losses:** `monitor` → `heartbeat` records status, ping, message, duration, retries and important transitions, with aggregation through the uptime calculator. `incident` is separate status-page communication with title/content/style/active/pin/timestamps; it is not automatically the same entity as an outage heartbeat. Pending retries and notification-worthy transitions are well defined. The Node backend couples Express/Socket.IO, RedBean/Knex, native SQLite, its own auth and many protocols/providers. Measured weight is much larger than a small HTTP-only pebble needs. [Heartbeat][k-heartbeat], [monitor transitions][k-monitor], [incident][k-incident], [calculator](https://github.com/louislam/uptime-kuma/blob/df601c58d9205562f34cfe5ef35264b341019d19/server/uptime-calculator.js), [manifest][k-pkg].
- **Keep / rewrite:** retain selected heartbeat/status/incident component designs and transition semantics; rewrite persistence into Drizzle, auth into Bedrock, Socket.IO into existing sync/HTTP, scheduling into detached jobs/services, and strip protocols/providers. Do not wrap the existing server inside `definePebble`: it still owns its own DB/auth/lifecycle. **15–25 days**; deleting features without preserving hidden dependencies is a major risk. [Server][k-server], [DB][k-db], [monitor][k-monitor], [Bedrock contract](../../../ARCHITECTURE.md#6-the-pebble-contract).
- **Licence / off-box:** MIT, copyright Louis Lam; retain copyright/permission/disclaimer in distributed derivatives, audit retained third-party assets, keep owner-requested attribution. No mandatory public source. Push monitors receive data at the Kuma server; they do not create an independently available watcher/page when it shares the home failure domain. Would need the same external Actions + Pages + Cloudflare path. [Licence](https://github.com/louislam/uptime-kuma/blob/df601c58d9205562f34cfe5ef35264b341019d19/LICENSE), [push route](https://github.com/louislam/uptime-kuma/blob/df601c58d9205562f34cfe5ef35264b341019d19/server/routers/api-router.js).

### Healthchecks — excellent deadlines, insufficient status-page starting point

- **Wins / appearance:** inspected its My Checks and check-detail screenshots: clear tables, late/down icons, period/grace, last ping and event history. Best model here for “job failed to report completion”. It receives start/success/fail pings, correlates run IDs and computes grace/deadlines. `Check`, `Ping` and `Flip` separate configuration, evidence and status transitions. [Screenshots](https://github.com/healthchecks/healthchecks/blob/5b9a198bca9dc959326f6492e460166373530499/README.md#healthchecks), [models][h-models].
- **Losses / keep / rewrite:** a push/dead-man's-switch service rather than an active HTTP prober with a rich public component-and-incident page. Python/Django templates, models, accounts, scheduler and worker cannot be retained as the pebble runtime. Preserve deadline/run-correlation ideas and selected event-history presentation; rewrite backend, active checks, public UI and incident communications. The README's development instructions still mention default SQLite, while the top-level supported-stack list names PostgreSQL/MySQL/MariaDB: do not equate “SQLite dev mode exists” with a supported Bedrock deployment. **15–25 days**, mostly new functionality and porting, so poor fork return despite useful ideas. [README][h-readme], [settings](https://github.com/healthchecks/healthchecks/blob/5b9a198bca9dc959326f6492e460166373530499/hc/settings.py), [alert worker][h-alert], [badge frontend](https://github.com/healthchecks/healthchecks/blob/5b9a198bca9dc959326f6492e460166373530499/templates/front/badges.html).
- **Licence / off-box:** BSD-3-Clause, copyright Pēteris Caune/contributors; preserve copyright, conditions and disclaimer in source and binary documentation; no use of contributors' names as endorsement. No mandatory public source. Avoid hosted-service branding: upstream explicitly says its hosted logo is outside the open-source project. Self-hosted on the laptop cannot detect its own death; hosted Healthchecks.io can watch an opaque Actions heartbeat, currently 20 jobs free. That complements inbound HTTP checks, not replaces them. [Licence](https://github.com/healthchecks/healthchecks/blob/5b9a198bca9dc959326f6492e460166373530499/LICENSE), [logo distinction](https://github.com/healthchecks/healthchecks/blob/5b9a198bca9dc959326f6492e460166373530499/templates/docs/self_hosted_configuration.md#site_logo_url), [hosted pricing](https://healthchecks.io/pricing/).

### Statping-ng — useful incident separation, weak maintenance/licence fit

- **Wins / appearance / model:** viewed the README-linked animated demo: light service list, explicit status pills, large uptime/latency statistics and graphs. Its README explicitly says to host status separately from the monitored server. ## 5. Concrete adaptation and external coverage

All items here are proposed fork work. Follow the [owner-approved generic webhook outbox](DESIGN.md#owner-decisions-on-the-build-plan-2026-11-07): comms is the first transport, not a daemon dependency. The pebble must consume scoped daemon API projections; it must never read daemon/other pebble SQLite files or duplicate the daemon's rule evaluator. Keep daemon incidents canonical for daemon rules; give imported external observations and manual status communications stable source IDs. [Architecture §5](../../../ARCHITECTURE.md#5-shape), [report 04](04-uptime-alerting.md).

- **One native pebble:** `definePebble`, creator-only administration, own Drizzle migrations/SQLite; records for check configuration, source-qualified observations, rollups, incident projections/manual communications, incident updates and import cursor. Reuse endpoint/result/event distinctions, but add explicit `unknown/stale`, maintenance and available-on-demand states. Separate raw observation outcome from thresholded incident state; one successful sample must not prematurely clear a two-success recovery policy. Status history reports observation coverage alongside availability. No extra shared core concept is introduced by this research; existing routes/jobs/services suffice. [Gatus model][g-sql], [Bedrock APIs](../../../docs/reference.md#10-composition-jobs-and-routes), [idle semantics](../../../docs/reference.md#8-daemon-and-hosting).
- **Bounded local work:** only explicitly configured HTTP checks; consume daemon readiness for sleeping pebbles instead of waking them. Network work outside write slots, concurrency 2, no overlap, 2-second local deadline, 3 failures/2 successes, following report 04. Use a detached cron job for minute cadence; a documented in-process service only if the proposed 30-second cadence is retained. Default cap proposal: 100,000 raw samples/7 days, daily rollups/incidents 365 days, **64 MiB monitoring DB budget** with explicit truncation/coverage state. This is separate from daemon telemetry's approved budget; capacity/RSS remain unverified. Do not add new framework options or another scheduler process. [Job/service contract](../../../docs/reference.md#10-composition-jobs-and-routes), [report 04's retention](04-uptime-alerting.md).
- **Independent canary:** implement the proposed `https://bedrock.<domain>/healthz`, exact 200 + versioned marker, no redirects, no cache, bounded response size and timeout. It checks daemon/registry viability, not every application. Initially publish one aggregate “Home cloud”; optionally add a specifically nominated end-to-end pebble later. Cache bypass matters: cached success already appears in Upptime's issue backlog. This endpoint is a prerequisite, not existing behavior at this checkout. [Report 04](04-uptime-alerting.md), [cache report](https://github.com/upptime/upptime/issues/1038).
- **Actions as the outside observer:** schedule `2-57/5 * * * *`, standard GitHub-hosted Linux runner, serialized run updates, no self-hosted laptop runner. Persist each scheduled observation plus a latest-observed timestamp in a small append/compact journal, counters and incident IDs; preserve enough external history to recover gaps after a prolonged home outage. Three failed observations open an incident; two successes close it. Nominal detection 10–15 minutes, without a guaranteed bound. A skipped/delayed run is missing evidence, not success. Persist data before publishing/notification, with retryable delivery state. [GitHub schedule limitations][gh-schedule], [Upptime concurrency/reference][u-workflow].
- **Notify and publish off-box:** GitHub issue creation/updates with explicitly configured owner subscriptions, or an approved external mail endpoint; never exclusively the on-box comms process. Test actual email delivery rather than assuming watch settings. Rebuild the tiny static Gatus-derived page from the external journal, **without contacting home**; show last check/publication time and compute stale → unknown in the browser even if publishing stops. Render initial static status conservatively, so disabled JS cannot leave an undated green assertion. Page build failure must not discard observations or suppress incident mail. [GitHub notification subscriptions](https://docs.github.com/en/subscriptions-and-notifications/how-tos/manage-your-subscriptions), [Pages static model][gh-pages], [Upptime's data/source separation][u-live].
- **Import after recovery:** the pebble periodically pulls the public journal using ordinary detached HTTP, verifies schema/size/source, deduplicates by target + workflow run/attempt + observation ID, and resumes from a cursor. Preserve `observed_at` and `received_at`; late or out-of-order imports must not revert current state. Fetch all retained gaps, not only latest status. No inbound ingestion credential is needed for this pull design, and no home availability is needed for external durability. Do not re-alert the owner for already-notified imported incidents. This is a new adapter, not a feature supplied by upstream Gatus. [Existing detached API](../../../docs/reference.md#10-composition-jobs-and-routes), [Gatus external results as reference][g-external].
- **Watch the watcher:** Cloudflare Tunnel Health Alert → owner email provides another external signal. Optionally ping hosted Healthchecks.io after every durably recorded probe run, regardless of target outcome; period 5 minutes/grace 15 minutes distinguishes a stalled prober from a down target. Its free 20-job tier is verified; end-to-end setup/delivery is **unverified**. Actions schedules can be delayed/dropped, and inactive public repositories can lose scheduled workflows after 60 days; journal commits help activity but do not prove watchdog reliability. [Cloudflare][cf-tunnel], [Healthchecks pricing](https://healthchecks.io/pricing/), [dead-man's switch](https://healthchecks.io/docs/), [schedule rules][gh-schedule].

## 6. Public fork, exposure and remaining owner choices

**Yes, public makes sense for the fork and the external aggregate page.** Keep Bedrock's repository and the private monitoring DB private. A public Gatus-derived fork can contain the pebble source, licence/attribution, build instructions, example targets and the outside workflow/export; only the intentionally public target's operational journal should be committed. Free standard Actions usage depends on the workflow's repository being public, not on every monitored app being public. Private repositories can use plan allowances/payment; a home-hosted runner would sacrifice the required failure-domain separation. Public GitHub Pages is available on GitHub Free. [Billing][gh-billing], [Pages][gh-pages], [Apache conditions][g-license].

| Surface | Public in the recommendation | Keep private / consequence |
|---|---|---|
| Fork source and build | Gatus-derived code, notices, changes, test fixtures and watcher | No Bedrock core publication required by this choice; no secrets or real private configuration |
| Target identity | “Home cloud”, actual public canary hostname/path | No automatic list of babel/typewriter/comms or private app URLs; publishing a hostname links this infrastructure to the owner's GitHub identity |
| Journal, Actions logs, Issues, Pages | Allowlisted status, observation timestamps, latency/uptime with coverage, redacted public incident updates | Downtime timings are intentionally disclosed; Git history remains discoverable after later deletion |
| Private pebble | Nothing automatically exported | Check URLs/headers, daemon readiness, internal names, job failures, logs, identities, acknowledgments and sensitive incident text stay private |
| Credentials | None in commits or page assets | GitHub secrets for optional external mail/watchdog; scoped default token permissions for repo/Issues/Pages. Never log response bodies/headers or echo secrets |

A secret URL variable is not sufficient redaction if URLs appear in errors, Git commits, incident bodies, generated favicons or graphs. The proposed exporter must **construct a separate allowlisted public DTO**, not serialize private models and hide UI fields. Gatus defaults expose hostname/condition details; upstream offers hide flags, but the fork should omit those fields from public data entirely. Upptime can reference secret target variables, yet the visible name, history, outputs and browser data still need auditing. [Gatus result serialization][g-result], [card hostname rendering][g-card], [hide flags][g-readme], [Upptime secret handling/updater][u-update].

Remaining choices, with recommended defaults:

1. **Confirm the public identity/domain and disclosure:** one aggregate “Home cloud”, canary URL and outage/uptime history; no individual pebbles initially. Public status approval is already in principle; this selects its exact data boundary. [Owner decisions](DESIGN.md#owner-decisions-on-the-build-plan-2026-11-07).
2. **Accept Actions latency/no SLA and select a mail recipient/subscription.** Enable Cloudflare email as well; opt into a hosted Healthchecks watchdog if stalled Actions detection matters. A real outage/recovery/email drill and stale-page test are acceptance work, not yet verified. [Schedule caveats][gh-schedule], [Cloudflare][cf-tunnel].
3. **Accept the selective Gatus derivative and 10–16-day scope**, including a real UI port and added incident lifecycle; do not approve it as “install Gatus and wrap it”. Retain upstream Apache-2.0, file provenance and a visible attribution. Fork drift/security review remains our responsibility. [Licence][g-license], [source model][g-sql].
4. **Set the monitoring DB budget and retention** separately from the already approved daemon telemetry/error budgets. Proposed 64 MiB is not a measurement. Require a representative workload memory test before treating the fork as lightweight; proposed acceptance target ≤80 MiB idle RSS is an experiment, not a promised Bun ceiling. [Approved budgets](DESIGN.md#owner-decisions-2026-11-07).

Main risks: UI port loses some upstream mergeability; Go implementation fixes require manual translation; Gatus's announcements do not supply the missing incident workflow; GitHub schedule/page/notification failures can give stale evidence; public journals permanently disclose outage timing; and the local pebble cannot serve during a box outage. The independent journal/page/notification path addresses that last risk, not the home UI. No new dependency was added in this task; any future dependency outside the allowed set still needs the repository's required approval. [Contract](../../../ARCHITECTURE.md), [repo rules](../../../AGENTS.md).
