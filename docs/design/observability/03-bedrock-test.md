# `bedrock test`: platform testing for pebbles

## Recommendation

All APIs/configuration below are **proposals**, not existing commands. Numbers are conservative starting defaults, not research-derived optima. Grounding: read the local architecture, reference §§8/10/11/13/14, author guide, dev launcher, auth routes and runtime at `fe936756e137fe85fa35821d9ae9a376e25bcbcc` ([architecture](https://github.com/MRoiban/bedrock/blob/fe936756e137fe85fa35821d9ae9a376e25bcbcc/ARCHITECTURE.md), [reference](https://github.com/MRoiban/bedrock/blob/fe936756e137fe85fa35821d9ae9a376e25bcbcc/docs/reference.md)).

- **Keep this a local CLI tool.** One Chromium worker, sequential viewport projects, no daemon scheduler, SaaS, sidecars or persistent test service. Install browsers explicitly on the development machine; keep Playwright/axe as development dependencies, outside production pebble releases. This follows Bedrock’s lightweight, SQLite-only contract ([architecture](https://github.com/MRoiban/bedrock/blob/fe936756e137fe85fa35821d9ae9a376e25bcbcc/ARCHITECTURE.md)).
- **CLI:** `bedrock test [path] [--grep <pattern>] [--project desktop|phone] [--json]`; `--list` discovers without executing; `--headed` diagnoses; `--repeat 10` investigates flakes; `--update-snapshots --yes` explicitly changes selected baselines. Exit 0 pass, 1 failed checks, 2 setup/configuration failure. Missing dependencies produce a repair command, never an interactive prompt. Copy familiar [Playwright CLI](https://playwright.dev/docs/test-cli) selection semantics.
- **Run two layers:** `bun test ./tests/unit` for cheap logic/runtime tests, then Playwright for built-in smoke checks and `tests/e2e/*.spec.ts`. Explicit directories prevent Bun discovering Playwright specs. API-only pebbles report browser checks as skipped with a reason. Keep ordinary unit tests independent of browser installation ([Bun discovery](https://bun.sh/docs/test), [Rails trade-offs](https://guides.rubyonrails.org/testing.html#when-to-use-system-tests)).
- **Own the server lifecycle.** Start the real dev daemon/pebble with a fresh temporary home/data directory, port 0 and source watching disabled; verify run identity and readiness; always stop children. Never reuse a developer’s running server. Current `devWorker` hardcodes `.bedrock/daemon` and watches source: extract its launcher with explicit test options; merely overriding `BEDROCK_HOME` is insufficient ([existing launcher](https://github.com/MRoiban/bedrock/blob/fe936756e137fe85fa35821d9ae9a376e25bcbcc/packages/bedrock/src/cli/dev.ts), [webServer](https://playwright.dev/docs/test-webserver)).
- **Seed SQLite per run, isolate per test.** Replay committed migrations into scratch data and run `tests/seed.ts`; fixtures use fixed IDs/dates. Create a clean, closed seed template, then copy into a fresh case directory before starting each test’s process. Include daemon identity DB and uploads. Stop/await services, sockets and DB before disposal; never copy an active WAL database by copying its main file alone. Restarting per case also clears in-memory state. Optimize only after measurement ([Dusk reset warning](https://laravel.com/docs/12.x/dusk#resetting-the-database-after-each-test), [Bedrock DB lifecycle](https://github.com/MRoiban/bedrock/blob/fe936756e137fe85fa35821d9ae9a376e25bcbcc/docs/reference.md#4-database)).
- **Authentication fixtures:** anonymous, owner, friend, outsider; use reserved `.test` emails. `loginAs(page, 'friend')` submits the existing same-origin dev login, preserving real session/access enforcement; separate contexts test two users. Include one UI login/logout test; do not inject trusted identity headers or share cookies across cases ([dev auth implementation](https://github.com/MRoiban/bedrock/blob/fe936756e137fe85fa35821d9ae9a376e25bcbcc/packages/bedrock/src/auth/routes.ts), [Playwright fixtures](https://playwright.dev/docs/test-fixtures)).
- **Control background work.** In the test launcher, disable cron dispatch; expose explicit job invocation. Require pebble-specific test substitutes for services that send mail, touch devices or call paid APIs. SQLite isolation cannot isolate external resources. Exercise real job/service startup separately with fakes ([Bedrock service limitations](https://github.com/MRoiban/bedrock/blob/fe936756e137fe85fa35821d9ae9a376e25bcbcc/docs/reference.md#11-application-sockets-and-long-lived-services), [Convex cron limitation](https://docs.convex.dev/testing/convex-test#limitations)).
- **Default smoke scope:** `/` anonymously and as the configured default fixture user; only declared additional routes/states. Check successful destination, application-ready assertion, browser errors, axe and responsive overflow. A login redirect alone is insufficient proof that the app rendered. Do not crawl arbitrary links or click potentially destructive controls ([Playwright assertions](https://playwright.dev/docs/test-assertions)).
- **Console gates:** install listeners before navigation on all test pages; fail unexpected `pageerror` and `console.error`. Record warnings and failed HTTP requests, but do not equate `requestfailed` with HTTP 500. Expected negative-test errors need a narrowly scoped matcher and count; attach source URL/line/stack ([Page events](https://playwright.dev/docs/api/class-page#page-event-console)).
- **Accessibility:** run `@axe-core/playwright` WCAG 2.0/2.1/2.2 A/AA tags at ready states; fail definite violations of every impact, report `incomplete` separately for review. Exceptions must identify rule + target + reason. Automated success is not WCAG certification; add keyboard/focus assertions to critical flows ([Playwright accessibility](https://playwright.dev/docs/accessibility-testing), [axe scope and claims](https://github.com/dequelabs/axe-core)).
- **Responsive:** run desktop 1280×800 and phone 390×844, DPR 1. Fail document-level horizontal overflow beyond 1 CSS px; allow named intentional scroll regions. Check important actions remain visible/usable through app-authored assertions. Offer 320px and WebKit as opt-in projects; Chromium phone emulation does not certify iOS ([emulation](https://playwright.dev/docs/emulation)).
- **Visuals:** capture failure screenshots immediately; compare opted-in named states with `toHaveScreenshot`. Missing selected baselines fail with update instructions. Commit approved PNG baselines under `tests/e2e/__screenshots__`, keyed by browser/OS/viewport; generated evidence stays ignored. Use one canonical OS/browser/font environment for acceptance ([visual comparisons](https://playwright.dev/docs/test-snapshots)).
- **Screenshot policy:** start with Playwright’s color-distance `threshold: 0.2`, `maxDiffPixels: 0`, hidden caret and disabled animations. Color threshold and permitted changed-pixel count are different controls; avoid a global percentage allowance that hides small missing controls. Await fonts, decoded images and an app-ready assertion; bundle fonts, fix locale/timezone/data, mask only named volatile regions ([assertion options](https://playwright.dev/docs/api/class-pageassertions#page-assertions-to-have-screenshot-1), [font instability](https://www.chromatic.com/docs/font-loading/)).
- **Animation/Anima:** use reduced motion in visual projects and Playwright animation disabling. Finite CSS/WAAPI animations finish; infinite ones reset temporarily. This does not promise control of canvas, Rive, GIFs or JS render loops. Provide an app-specific `prepareScreenshot(page)` fixture that puts each animated control into a named stable state through its actual runtime API; test hover/click/keyboard behavior separately with motion enabled. Do not replace every animated control with an empty box. No Anima API was identified in the inspected checkout; adapter details remain open ([Playwright behavior](https://playwright.dev/docs/api/class-pageassertions#page-assertions-to-have-screenshot-1), [Chromatic animation handling](https://www.chromatic.com/docs/animations/)).
- **Flake policy:** zero retries by default; retain the first failure. Optional single diagnostic retry reports `flaky` and remains nonzero. Use locator assertions and explicit readiness, not sleeps/network-idle on live-query apps. Quarantine requires an owner, reason and expiry, and remains visible ([Google mitigation costs](https://testing.googleblog.com/2016/05/flaky-tests-at-google-and-how-we.html), [Playwright retries](https://playwright.dev/docs/test-retries)).
- **Agent reports:** one `{ok,value}` or `{ok:false,error}` object on stdout; child logs go to stderr/files. Version the report: run ID, source hash/dirty status, tool versions, seed, configuration, per-check ID/status/location/duration/attempts, coverage states, artifact paths, and reproduction argv. Normalize Playwright JSON plus Bun JUnit; do not parse colored terminal output ([reporters](https://playwright.dev/docs/test-reporters), [Bun JUnit](https://bun.sh/docs/test#junit-xml-reports-gitlab-etc)).
- **Evidence:** traces `retain-on-failure`, screenshots `only-on-failure`, actual/expected/diff PNGs for visual failures, console/server logs and axe node JSON. Video opt-in. Store locally in `.bedrock/tests/<run>/`; prune oldest completed runs beyond 7 days or 500 MiB, preserving the current run and reporting truncation. No uploads. Include e.g. `bedrock test tests/e2e/notes.spec.ts --grep 'friend cannot delete' --project phone --json`; explain that the same checkout/seed/config are needed ([trace viewer](https://playwright.dev/docs/trace-viewer)).
- **Extension without a new testing language:** proposed optional `bedrock.test.ts` exports plain TypeScript `{seed, users, pages, prepareScreenshot}`; validate unknown keys. Conventional test directories and defaults need no config. A small development-only `bedrock/testing` exports Playwright `test`/`expect` with `loginAs`, seeded-server and axe fixtures. Pebbles add ordinary Playwright tests; runtime tests use existing `startPebble({dir,dataDir,port:0})`/`execute`, wrapped by an ergonomic identity helper. Keep real SQLite/queue/validation; do not reproduce the database in mocks ([existing author API](https://github.com/MRoiban/bedrock/blob/fe936756e137fe85fa35821d9ae9a376e25bcbcc/packages/bedrock/AGENTS.md), [convex-test](https://docs.convex.dev/testing/convex-test)).

Illustrative config; all names proposed:

```ts
import seed from './tests/seed';
export default {
  seed,
  users: { owner: 'owner@example.test', friend: 'friend@example.test' },
  pages: [{ path: '/', user: 'friend', ready: '[data-testid="notes-ready"]', visual: true }],
};
```

## Sources studied

- **Rails:** [system tests/fixtures guide](https://guides.rubyonrails.org/testing.html). Browser infrastructure and named data are platform features. Copy predictable setup; avoid giant fixture universes. Current guide explicitly warns about slow, brittle system tests and says scaffolds no longer generate them by default.
- **Phoenix/Ecto:** [SQL Sandbox](https://hexdocs.pm/ecto_sql/Ecto.Adapters.SQL.Sandbox.html) assigns transactional connections to owners and collaborating processes. Copy explicit ownership/cleanup. Its concurrent sandbox guarantee is PostgreSQL-specific; it is not a SQLite isolation recipe.
- **Laravel Dusk:** [database reset/authentication](https://laravel.com/docs/12.x/dusk). Copy browser login helpers and environment management. Its explicit warning that transactional refresh does not span HTTP requests strongly supports fresh test databases.
- **Next.js:** [testing guide](https://nextjs.org/docs/app/guides/testing) distinguishes unit/component/integration/E2E tooling. Copy layered guidance; avoid presenting a single browser smoke command as complete application coverage.
- **Remix v2:** [`createRemixStub`](https://v2.remix.run/docs/other-api/testing/) supplies router context for component tests, while navigation requires E2E tooling. Copy focused helpers; mocks do not establish server/auth correctness. Version scoped: these are v2 docs, not a claim about later Remix designs.
- **SvelteKit ecosystem:** official CLI [Playwright](https://svelte.dev/docs/cli/playwright) and [Vitest](https://svelte.dev/docs/cli/vitest) add-ons scaffold established tools. Copy conventions over a custom assertion DSL; avoid forcing framework-specific component infrastructure into Bedrock core.
- **Convex:** [convex-test](https://docs.convex.dev/testing/convex-test) offers query/mutation calls, data seeding and `withIdentity`. Closest ergonomic analogue. Its documented mock limitations include limits, runtime differences and no cron support; Bedrock can use its real local runtime instead.
- **Deno:** [built-in testing](https://docs.deno.com/runtime/test/) normalizes discovery, filtering and test steps. Copy one discoverable entry point; adopting another runtime adds no value to a Bun platform.
- **Bun:** [runner/JUnit](https://bun.sh/docs/test) provides native TypeScript tests, hooks and snapshots. Copy fast tests and structured result ingestion. Jest compatibility is incomplete; check supported Bun versions rather than assuming every current feature exists on Bedrock’s minimum Bun 1.2.
- **Playwright:** [fixtures](https://playwright.dev/docs/test-fixtures), [webServer](https://playwright.dev/docs/test-webserver), [reporters](https://playwright.dev/docs/test-reporters). Copy browser reuse with fresh contexts, deterministic startup and attachments. Browser-context isolation does not reset server data; server reuse risks testing stale code.
- **axe-core:** [README/manifesto](https://github.com/dequelabs/axe-core), [Playwright integration](https://playwright.dev/docs/accessibility-testing). Deque states zero false positives “bugs notwithstanding,” approximately 57% automatic WCAG-issue detection, and `incomplete` for uncertainty. These are maintainer claims, not an independently measured Bedrock false-positive rate; manual testing remains necessary.
- **Playwright visuals:** [comparisons](https://playwright.dev/docs/test-snapshots), [API](https://playwright.dev/docs/api/class-pageassertions). Copy local baselines, stable consecutive captures and diff evidence. OS, fonts, hardware and rendering mode can change output; two matching captures can still show a stable loading screen.
- **Lost Pixel:** [README](https://github.com/lost-pixel/lost-pixel), [configuration source](https://github.com/lost-pixel/lost-pixel/blob/main/src/config.ts). Standalone core accepts custom captures; schema separates baseline/current/diff paths. Threshold defaults to zero and overloads ratio/pixel units. Copy local evidence; avoid ambiguous threshold units and default fixed capture delays.
- **reg-suit:** [README/config](https://github.com/reg-viz/reg-suit). Image comparison/reporting with Git-derived keys and publishing plugins; rate/pixel thresholds default to zero. Copy explicit baseline identity; avoid S3/GitHub publishing infrastructure for a local single-owner tool.
- **Argos:** [overview](https://argos-ci.com/docs), [baseline selection](https://argos-ci.com/docs/learn/platform-fundamentals/baseline-build). Captures upload to a comparison/review platform; baseline eligibility considers history, test success and rejection. Copy deliberate baseline approval; avoid remote screenshot storage as a default dependency.
- **Chromatic:** [threshold](https://www.chromatic.com/docs/threshold/), [fonts](https://www.chromatic.com/docs/font-loading/), [animations](https://www.chromatic.com/docs/animations/). Documents sensitivity/noise trade-offs (default `.063`), font instability and motion freezing. Copy deterministic capture; its threshold is not interchangeable with Playwright’s color-distance/pixel budget.
- **BackstopJS:** [README](https://github.com/garris/BackstopJS) provides viewports, scenarios, readiness selectors, local reference/test directories and approval. Default mismatch tolerance is `0.1` **percent**, with equal dimensions required. Copy scenario readiness and review; avoid broad delays and percentage thresholds as substitutes for determinism.
- **Google:** [2016 mitigation report](https://testing.googleblog.com/2016/05/flaky-tests-at-google-and-how-we.html) reports 1.5% flaky runs and 84% of observed pass→fail transitions involving flakes; warns retries/quarantine can conceal defects. [2017 follow-up](https://testing.googleblog.com/2017/04/where-do-our-flaky-tests-come-from.html) correlates larger/resource-heavier tests with flakiness. Historical Google measurements, not Bedrock forecasts.
- **Luo et al., FSE 2014:** [paper](https://www.cs.cornell.edu/courses/cs5154/2021sp/resources/LuoETAL14FlakyTestsAnalysis.pdf) examines 201 likely-fix commits across 51 projects; async wait, concurrency and order dependence dominate classified causes. Copy synchronization and state isolation; this is a selected commit sample, not population incidence.
- **Follow-ups:** [UI study, 2021](https://arxiv.org/abs/2103.02669) studies 235 samples from 62 projects and highlights costly UI reruns; [JavaScript study, ICSME 2022](https://arxiv.org/abs/2207.01047) analyzes 452 commits, finding concurrency dominant, plus OS/network causes. Copy targeted reproduction, stable environments and external-service fakes; avoid transplanting percentages across domains.

## Anti-patterns

- **Retry-until-green:** [Google](https://testing.googleblog.com/2016/05/flaky-tests-at-google-and-how-we.html) explains both delayed detection and suppressed real defects. A passing diagnostic rerun is evidence of nondeterminism, not proof the change is safe.
- **One shared SQLite + parallel browser tests:** [Ecto’s ownership constraints](https://hexdocs.pm/ecto_sql/Ecto.Adapters.SQL.Sandbox.html) and [Dusk’s transaction warning](https://laravel.com/docs/12.x/dusk#resetting-the-database-after-each-test) invalidate simplistic rollback isolation. Future parallelism needs independent homes/databases/ports per worker, with reset per case.
- **Approve all images after any failure:** baseline updates can bless a loading screen or missing content. Require functional readiness first, selected updates and reviewed diffs; [Argos](https://argos-ci.com/docs/learn/platform-fundamentals/baseline-build) similarly excludes failing/rejected candidates.
- **Global masking/relaxed thresholds:** [Chromatic](https://www.chromatic.com/docs/threshold/) explicitly trades sensitivity for fewer false positives. Freeze inputs before loosening assertions; never suppress all console errors or all low-impact accessibility findings to obtain green output.

## Open questions for the owner

1. Which two pebbles justify the initial core feature, and which three critical user journeys should anchor it?
2. What exactly is Anima here: package, renderer and exposed state/seek/pause API? Which controls need stable visual states versus motion-behavior tests?
3. Which canonical OS/font/browser environment owns visual baselines across Linux, macOS and Windows?
4. Which jobs/services need substitutes, and should browser dependencies live in a separate first-party development package? Validate Playwright’s supported runner/runtime combination instead of assuming it runs under Bun.
