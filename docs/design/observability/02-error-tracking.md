# Error tracking for Bedrock

## 1. Recommendation

Research date: 2026-11-07. **Adopt a native, bounded error client and SQLite issue store; defer Sentry-envelope compatibility.** All numeric limits below are proposed starting defaults, not measured Bedrock capacity.

Grounding: read local `ARCHITECTURE.md`, reference §§8/10/11/13/14, author-guide logs/dev/jobs sections, and runtime code. Bedrock has one daemon, IPC-only child control, sleeping pebbles, serialized application writes, release headers, and Git provenance. Its HTML entry uses Bun's runtime HTML bundler, not an existing explicit deploy-time `Bun.build` pipeline. [Architecture](https://github.com/MRoiban/bedrock/blob/main/ARCHITECTURE.md), [reference](https://github.com/MRoiban/bedrock/blob/main/docs/reference.md), [web loader](https://github.com/MRoiban/bedrock/blob/main/packages/bedrock/src/runtime/web.ts#L35-L39).

- **Protocol:** `POST /_bedrock/errors` on each pebble origin, intercepted by the daemon without waking its child. Versioned JSON `{v:1, events:[...]}`; fields: UUID, capture mechanism, exception type/message/cause chain, frames, handled flag, route template, page/server release, optional request ID. Derive pebble from routed Host; label browser payloads untrusted. Keep `captureException(error, {fingerprint?})` in `bedrock/client`. Sentry's mature SDK coverage is the strongest argument for compatibility; Bugsink proves it need not require big infrastructure. But framing, authentication, item types, quotas, and artifact APIs are additional contracts for this Bun-only platform. [Relay ingest](https://github.com/getsentry/relay/blob/master/relay-server/src/endpoints/envelope.rs#L61-L72), [Bugsink ingest](https://github.com/bugsink/bugsink/blob/main/ingest/views.py#L264-L440).
- **Browser capture:** register additive `error` and `unhandledrejection` listeners before mounting; cover the same failures as `window.onerror` without replacing app handlers. Distinguish resource-load errors from exceptions. Non-Error rejection values get bounded, scrubbed text, never arbitrary object dumps. Cross-origin opaque “Script error.” has low diagnostic confidence. Add a React boundary reporting exception plus component stack; global listeners remain necessary for event handlers and asynchronous callbacks. Deduplicate the same Error object with a WeakSet across boundary/manual/global capture. [SDK handlers](https://github.com/getsentry/sentry-javascript/blob/develop/packages/browser/src/integrations/globalhandlers.ts#L20-L109), [React limits](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary).
- **Console/fetch:** leave automatic `console.error` reporting off in production; enable explicitly or in `bedrock test`, preserving the original console and guarding recursion. Instrument Bedrock client requests first; do not patch every fetch. Fetch rejection, HTTP 500, expected 400, abort and offline are distinct outcomes. Aggregate network failures; create an issue for unexpected same-origin 5xx or explicit capture. A server request ID links its browser symptom to the original exception rather than counting two defects. [Console integration](https://github.com/getsentry/sentry-javascript/blob/develop/packages/core/src/integrations/captureconsole.ts), [existing client behavior](https://github.com/MRoiban/bedrock/blob/main/docs/reference.md).
- **Server capture:** report unexpected throws at query/mutation/route/job/socket/service/startup boundaries through existing IPC, before error-to-response conversion discards context. Exclude expected typed validation/auth failures. Record process exit/signal/restart separately in the supervisor; a proxy 5xx alone cannot reveal an exception stack. Fatal capture is best effort: preserve Bun's termination behavior, never keep a corrupted child serving, never await telemetry in the application transaction. [Runtime catch](https://github.com/MRoiban/bedrock/blob/main/packages/bedrock/src/runtime/index.ts#L57-L73), [jobs/services contract](https://github.com/MRoiban/bedrock/blob/main/docs/reference.md).
- **Batch/transport:** memory queue of 20 events, 16 KiB/event, flush at five events or two seconds, max 48 KiB UTF-8/batch. Normal fetch reads acknowledgments; on visibility becoming hidden use `sendBeacon`, falling back to `fetch({keepalive:true})` if queueing fails. Share an in-flight byte budget below 60,000; a successful beacon return means queued, not durably received. No unload handler, localStorage queue, or telemetry-about-telemetry. [SDK transport](https://github.com/getsentry/sentry-javascript/blob/develop/packages/browser/src/transports/fetch.ts#L19-L60), [Beacon lifecycle](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/sendBeacon).
- **Backpressure:** client: 20 reports/minute, burst 10, with repeated signatures coalesced into counts. Daemon: 120 reports/minute/pebble, burst 30; global 600/minute and 1 MiB pending queue. Independently reserve server-event capacity so browser spam cannot starve crashes. Reject oversized bodies before parsing; reject compression initially. Enforce byte, depth, frame and string caps. Return 429 + `Retry-After`; client pauses, retries transient failure twice with jitter, then drops. Count drops without emitting one log per rejection. [SDK rate-limit handling](https://github.com/getsentry/sentry-javascript/blob/develop/packages/core/src/transports/base.ts), [GlitchTip rejection-log complaint](https://gitlab.com/glitchtip/glitchtip-backend/-/work_items/497).
- **Endpoint safety:** require matching Origin and existing access policy for private pebbles; allow anonymous reports on public pebbles with quotas. A DSN/public browser token is routing information, not authentication. Browser identity never grants issue-read access. Use creator/scoped-token authorization for inspection; discard IP after bounded in-memory abuse control. Origin checks reduce cross-site pollution but cannot stop scripted forgery. [Bedrock trust model](https://github.com/MRoiban/bedrock/blob/main/ARCHITECTURE.md#8-trust-model), [Relay request metadata](https://github.com/getsentry/relay/blob/master/relay-server/src/endpoints/envelope.rs#L75-L112).
- **Privacy:** allowlist fields; no cookies, Authorization, request/response bodies, form/DOM values, full referrers, session replay, email or persistent user identifier. Route templates replace user-bearing paths; remove URL credentials/query/hash. Scrub messages, stacks, causes and allowed tags on client and again before persistence, alerts or CLI output: emails, tokens/JWTs, secret-like assignments and known secret values where available. Preserve error codes; do not serialize arbitrary objects/getters. Redaction is imperfect: support a synchronous `beforeSend` filter and avoid collecting sensitive context in the first place. [Sentry sensitive-data guidance](https://docs.sentry.io/platforms/javascript/data-management/sensitive-data/).
- **SQLite model:** one daemon-owned observability database, separate from business writes: `issues(id,pebble,environment,runtime,state,first_seen,last_seen,first_release,last_release)`, `fingerprints(pebble,environment,runtime,version,key,issue_id)` with unique key, `events(id,issue_id,release,received_at,scrubbed_json)`, hourly issue/release counters and drop counters. Short batched transactions; unique event IDs make retries idempotent. Separate fingerprint aliases enable manual merging without changing event identity. [PostHog many-to-one model](https://posthog.com/docs/error-tracking/fingerprints), [SQLite precedent](https://www.bugsink.com/docs/settings/).
- **Stack normalization:** parse V8/Bun and Firefox/Safari formats into ordered `{file,function,line,column,in_app}` frames; retain scrubbed generated and mapped frames. Map before fingerprinting; canonicalize source paths relative to project, remove deployment roots/origins/query strings, collapse adjacent recursion and exclude capture/runtime wrappers from grouping. Preserve displayed coordinates; never blindly hash the raw stack string. [Sentry grouping implementation](https://github.com/getsentry/sentry/blob/master/src/sentry/grouping/strategies/newstyle.py), [Rollbar normalization](https://docs.rollbar.com/docs/grouping-algorithm).
- **Fingerprint v1:** SHA-256 of runtime + exception type + up to five nearest contributing application frames, each using canonical source path, function and whitespace-normalized source line. Exclude release and numeric coordinates when mapped context exists. For unmapped bundles, retain exact asset identity plus coordinates and flag unstable grouping. Without a usable stack, use type + conservatively normalized message + operation template. Keep cause chains for diagnosis; start from deepest usable cause. Explicit bounded fingerprints override or extend default. Prefer visible splits over hiding unrelated bugs; expose contributing inputs and a grouping version. [Rollbar tradeoff](https://docs.rollbar.com/docs/grouping-algorithm), [Sentry stack precedence](https://github.com/getsentry/sentry/blob/master/src/sentry/grouping/strategies/newstyle.py), [Bugsink message normalization](https://www.bugsink.com/docs/grouping/).
- **Bun source maps:** generate external maps for the exact deployed bundles and keep a private manifest `(pebble,release,asset content hash/debug ID) → map`. Bun documents external maps and bundle debug IDs; verify emitted IDs and mapping with the installed Bun version. Do not assume runtime HTML bundling exposes those artifacts: extracting them or moving production HTML builds into deployment is prerequisite work. Keep maps outside served roots; never fetch event-supplied URLs. Bound map size/cache, normalize line/column conventions, and check a deliberately thrown minified production error against TypeScript. Missing maps must remain visible. [Bun bundler](https://bun.sh/docs/bundler#sourcemap), [Bugsink deterministic mapping/SSRF avoidance](https://www.bugsink.com/docs/sourcemaps/).
- **Release tracking:** reuse `BEDROCK_RELEASE_ID`, page/server release observations and `{commit,branch,dirty}` provenance. Persist both page and serving release: a stale tab may report old code after deploy. Release is metadata, not part of the stable mapped fingerprint. Reopen a resolved issue on recurrence, marking whether it came from a stale release; rollback does not imply a fix. Keep map artifacts 30 days even though code retains only three releases. [Existing release contract](https://github.com/MRoiban/bedrock/blob/main/docs/reference.md), [author provenance](https://github.com/MRoiban/bedrock/blob/main/packages/bedrock/AGENTS.md).
- **Retention/sampling:** initially capture every admitted unexpected error, then preserve counts but retain first/latest examples and at most 20 detailed events/issue/release/day. Payloads: 14 days; issue/hour aggregates: 90 days; 100 MiB payload budget/pebble and 1 GiB globally, evict oldest details first. Cap new issues at 100/pebble/day and account for overflow. Counts are admitted/coalesced reports, not exact users or all real failures; expose rate-limited, sampled and queue-lost totals separately. [WER progressive collection](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/sosp153-glerum-web.pdf), [Bugsink ingest quotas](https://github.com/bugsink/bugsink/blob/main/ingest/views.py#L222-L283).
- **Noise:** quarantine extension-only stacks (`chrome-extension:`, `moz-extension:`, Safari equivalents); mixed app/extension stacks remain inspectable. Exact ResizeObserver loop messages go to a counted, non-alerting bucket with one daily example, not blanket deletion: real loops can exist. Tag known bots/synthetic tests, suppress their alerts, and retain separately; user-agent classification is advisory. Exclude telemetry/health endpoints and normal abort/reconnect failures. [Relay extension filters](https://github.com/getsentry/relay/blob/master/relay-filter/src/browser_extensions.rs), [ResizeObserver failure report](https://github.com/getsentry/sentry-javascript/issues/12037), [browser behavior](https://developer.mozilla.org/en-US/docs/Web/API/ResizeObserver).
- **Operations:** `bedrock errors <pebble> --json`, `errors show <id>`, `errors resolve/ignore/merge`; filters `--release`, `--since`, `--runtime`, cursor pagination, stable IDs and grouping explanation. Alert through comms on new/regressed unhandled issues; cooldown 30 minutes/issue, then digest repeats. Collector failures expose one status warning plus drop totals, never break requests. [Honeybadger noise rationale](https://www.honeybadger.io/explain/error-grouping/), [Bedrock agent contract](https://github.com/MRoiban/bedrock/blob/main/ARCHITECTURE.md#9-agent-friendliness-non-negotiable).
- **RUM:** do not collect LCP/INP/CLS by default in v1. If two pebbles need browser performance, opt in to locally bundled standard `web-vitals`; at small volume collect all consenting/eligible page views, with metric ID upserts rather than summing repeated callbacks. Keep release, route template, metric and coarse browser only; no DOM attribution. Separate histograms and sample counts from issues; no p75 alerts until 100 samples per reporting window. Missing INP/unsupported metrics are missing, not zero; iframe visibility limits apply. [web-vitals implementation/limitations](https://github.com/GoogleChrome/web-vitals#readme).

## 2. Sources studied

- **Sentry SDK, Relay, grouping:** code links above cover global handlers, React boundary, console capture, transport and ingest. Copy mechanism labels, bounded transport and application-frame grouping; avoid promising Sentry behavior from JSON-field similarity. Server grouping is substantially more than hashing messages; it has variants, enhancements and exception-chain handling. Envelope compatibility does not supply that behavior.
- **GlitchTip:** [installation](https://glitchtip.com/documentation/install/) requires PostgreSQL; Redis/Valkey is now optional, so “always needs Redis” is outdated. Copy SDK interoperability and [custom fingerprints](https://glitchtip.com/blog/2023-07-15-glitchtip-3-3/). Avoid its unsuitable database dependency here. [Issue 175](https://gitlab.com/glitchtip/glitchtip-backend/-/issues/175) explicitly accepted grouping-history discontinuity; Bedrock should preserve aliases. Backend GitLab source fetch returned only a loading shell; these conclusions use first-party docs/issues, not an unverified code reading.
- **Bugsink:** [SQLite defaults](https://www.bugsink.com/docs/settings/), [bounded envelope parser](https://github.com/bugsink/bugsink/blob/main/ingest/views.py), [versioned grouping](https://www.bugsink.com/docs/grouping/). Copy simple storage and migration discipline. Its type/message-based default is economical but cannot distinguish identical messages from unrelated throw sites; normalization is not privacy scrubbing.
- **Highlight.io:** [Go matching code](https://github.com/highlight/highlight/blob/main/backend/public-graph/graph/resolver.go) considers first/rest frame code and metadata, JSON fingerprints, and embedding alternatives. Copy use of several frame signals; avoid embedding infrastructure for a personal server. Its former grouping-doc URL now redirects to LaunchDarkly, so source code is the evidence used here.
- **PostHog:** [fingerprints](https://posthog.com/docs/error-tracking/fingerprints) prioritizes resolved application frames and models merged fingerprints explicitly. Copy those two choices; avoid relying on grouping consistency before artifact resolution. This is a product-design reference, not a recommendation to deploy its analytics stack.
- **Rollbar / Honeybadger:** [Rollbar](https://docs.rollbar.com/docs/grouping-algorithm) omits shifting line numbers, uses code context and deliberately favors splits when uncertain. [Honeybadger](https://docs.honeybadger.io/lib/javascript/errors/customizing-error-grouping/) includes location/class/component by default. Their differing heuristics argue for explainable overrides, not a universal “correct hash.”
- **WER, SOSP 2009:** [paper §§2–3, 6.3](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/sosp153-glerum-web.pdf) distinguishes client labeling from server classification and uses progressive evidence. Copy limited examples plus counts and rebucketing; avoid transplanting its vast empirical heuristic set. It documents both split and collision weaknesses.
- **ReBucket, ICSE 2012:** [paper](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/07/rebucket-icse2012.pdf) compares call stacks with depth/offset-aware similarity and hierarchical clustering. Reported mean F-measure is about 0.88 across five Microsoft products. Copy awareness that exact signatures miss duplicates; avoid automatic fuzzy merging and cubic worst-case clustering. Native-crash results do not validate JavaScript grouping.
- **web-vitals:** [source/readme](https://github.com/GoogleChrome/web-vitals) supplies metric lifecycle/batching and documents iframe/API limitations. Copy the library if RUM is justified; avoid hand-written approximations, repeated-listener leaks and presenting a few friends' samples as population statistics.

## 3. Anti-patterns

- **“Just accept Sentry envelopes.”** Bugsink's real parser validates sizes before/after decompression, handles unsupported items and advertises transaction/span backoff. An adapter later must test these plus authentication, CORS, event IDs and source-map upload with pinned stock SDKs. Wire compatibility is feasible, but not free. [Code](https://github.com/bugsink/bugsink/blob/main/ingest/views.py#L264-L440).
- **Reporting every repeat and every rejection.** ResizeObserver storms and rejection logging can turn monitoring into workload. Coalesce and count; never recursively report collector failure. [SDK issue](https://github.com/getsentry/sentry-javascript/issues/12037), [GlitchTip issue](https://gitlab.com/glitchtip/glitchtip-backend/-/work_items/497).
- **Changing grouping silently or grouping by release/raw message.** Variable IDs split issues; releases split recurrence; broad message normalization can merge distinct bugs. Version grouping, preserve aliases and allow corrections. [Bugsink transition](https://www.bugsink.com/docs/grouping/), [Rollbar conflict policy](https://docs.rollbar.com/docs/grouping-algorithm).
- **Public maps or URL-based symbolication.** Hidden comments do not protect files still served; event-controlled fetches create SSRF risk. Resolve private, exact artifacts only. [Bugsink design](https://www.bugsink.com/docs/sourcemaps/).

## 4. Open questions

1. Which two real pebbles justify core adoption, and should browser capture start automatically with the existing client or require explicit initialization?
2. Can the supported Bun runtime expose exact HTML-bundle maps privately, or is a deploy-time production build acceptable? Validate before claiming automatic symbolication.
3. Are 100 MiB/pebble and 1 GiB global appropriate for the home disk? Should observability details be excluded from backups while issue state is preserved?
4. Is stock Sentry SDK reuse already needed by a real pebble? If yes, add an explicitly error-only adapter over the native schema, disabling tracing/replay and testing supported SDK versions; do not replace the internal model.
